## P0 — Critical

### 1) Fix analytics middleware type compatibility and storage integration
- Labels: bug, security, backend, priority:P0
- Summary: The enhanced analytics middleware (`authenticateAnalyticsJWT`) and routes use extended request types and analytics storage methods that are not reflected in the base `IStorage`, causing TS errors and blocking builds.
- Scope:
  - Make middleware handlers conform to Express `RequestHandler` types to avoid structural mismatches.
  - Reconcile `storage` typing: use `IStorage & IAnalyticsStorage` for the exported `storage` instance, or narrow casts inside analytics paths.
  - Ensure referenced methods (`getSession`, `updateSession`, `getSessionActivity`, `revokeSession`, token/api-key helpers) are available at type level where used.
- Acceptance Criteria:
  - `npm run check` passes with zero type errors related to analytics auth and storage.
  - All `/api/analytics/*` routes compile using `authenticateAnalyticsJWT` and `requireAnalyticsScope` (enhanced) without casts to `any` in route files.
  - No breaking changes to non-analytics middleware signatures.
- Affected: `server/middleware/analyticsAuthMiddleware.ts`, `server/storage.ts`, `server/storage-extensions.ts`, `server/routes.ts`.

### 2) Standardize logger context typing or usage
- Labels: bug, refactor, backend, priority:P0
- Summary: Many `logger.*` calls pass fields not defined in `LogContext` (e.g., `email`, `error`, `expiredAt`, `metricsCount`), causing TS errors.
- Acceptance Criteria:
  - Define an extensible `LogContext` that safely accepts extra fields, or wrap calls with a `context: Record<string, unknown>` parameter.
  - `npm run check` has no logger-related type errors.
- Affected: `server/lib/logger.ts` (or typings), multiple call sites.

### 3) Resolve missing runtime deps or provide fallbacks (bcrypt, ioredis)
- Labels: build, bug, security, priority:P0
- Summary: TS errors for missing modules `bcrypt` and `ioredis`. Decide on optional deps or dev-friendly fallbacks.
- Acceptance Criteria:
  - Use `bcryptjs` for pure JS fallback or mark as optional and guard usage.
  - Stub or feature-flag `ioredis` usage in dev; ensure type safety.
  - `npm run check` passes locally without requiring external services.
- Affected: `server/services/authService.ts`, `server/lib/cache.ts`, package.json.

### 4) Replace health check DB probe using non-existent `getAllUsers`
- Labels: bug, backend, ops, priority:P0
- Summary: `server/routes.ts` health endpoint calls `storage.getAllUsers()` which does not exist.
- Acceptance Criteria:
  - Replace with a lightweight probe supported by both Mem and DB storage (e.g., list 1 lead or a no-op `ping()` added to storage).
  - Health endpoint returns 200 in dev with MemStorage.
- Affected: `server/routes.ts`, `server/storage.ts`.
